# Context and Token Policy

## Request Classification
Identify explanation, inspection, implementation, bounded documentation maintenance, initial documentation or explicit full refresh. Select only applicable directives and skill modes; an ordinary feature request does not imply full refresh.

## Progressive Reading
1. Search filenames, headings and symbols with rg in the verified workspace.
2. Read relevant Docs/index.md links and category Overview sections.
3. Read necessary details and focused Git history.
4. Inspect relevant implementation and asset interfaces.
Load only necessary templates and official documentation sections. Do not create duplicate English project knowledge.

## Evidence Required by Situation
| Situation | Minimum investigation |
|---|---|
| Documented explanation | Relevant document; disclose when implementation was not checked |
| Code or asset change | Target plus required callers, dependencies, ownership and bindings |
| Initial category document | Sufficient related implementation to explain the category accurately |
| Existing category refresh | Baseline changes, local changes and current implementation/prose comparison |
| Contradiction or missing evidence | Expand related source/assets until resolved or report uncertainty |

## Reuse and Freshness
Reuse already verified conversation context unless changes, stale evidence or contradictions justify rereading. New sessions cannot assume old context. A recent document date alone does not prove freshness. Git history locates possible changes; it does not replace implementation checks.

## Search Boundaries and Expansion
Start narrow, not with a full repository dump. Broaden when baseline is missing/invalid, documentation omits topics, code disagrees or dependencies cross categories. Do not require the user to supply paths the agent can find. If ambiguity remains after bounded search, report candidate locations and ask.

## Expensive and Generated Content
Skip Binaries, Intermediate, Saved, DerivedDataCache, IDE caches and vendor/generated output unless directly relevant. Asset existence does not establish Blueprint graph content. Inspect live state if needed; do not hide an asset inspection gap to save tokens. Never generate scans/sites or install search tooling merely to answer a question.

## Output Economy
Use relevant excerpts and compact results. Summarize routine checks, retain material evidence and limits. Token savings must not remove durable knowledge, necessary investigation or required verification.
