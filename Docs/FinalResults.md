# 최종 결과 및 같은 방 대기 복귀

## 게임 흐름

`대기 → 1R~4R(각 결과 6초) → 최종 누적 순위·MVP → 호스트가 방 대기로 돌아가기 → 걷기 대기 → 새 경기`

4라운드가 끝나면 마지막 라운드 결과를 6초 보여준 후 `FinalResult`로 전환한다. 호스트와 모든 참가자가 같은 최종 순위표를 받는다. 최종 결과는 호스트가 복귀하거나 방을 나갈 때까지 유지된다.

## 최종 순위와 MVP

- 서버가 누적 점수 내림차순으로 최종 순위를 확정한다. 마지막 라운드 순위표(`Scoreboard`)와 최종 순위표(`FinalStandings`)는 별도로 유지한다.
- 총점이 같으면 공동 순위다. 예: 14 / 11 / 11 / 4점 → 1 / 공동 2 / 공동 2 / 4위.
- 누적 1위에게 MVP를 표시한다. 최고 점수 동률이면 모두 공동 MVP다. 플레이어 ID는 동점 행의 표시 순서만 안정화하고 동점 순위를 나누지 않는다.
- 중도 퇴장자의 확정 점수도 보존하고 최종 순위에 포함한다. 퇴장 표시는 순위와 점수를 다시 계산하지 않으며, 최고 점수였다면 MVP도 유지한다.
- MVP 행을 금색으로 강조한다. 최종 화면은 라운드 점수 대신 MVP 여부와 총점을 보여준다.

## 같은 방 대기 복귀

- 최종 결과의 **방 대기로 돌아가기** 버튼은 호스트에게만 표시한다. 참가자는 호스트를 기다린다는 안내를 본다.
- 서버 RPC에서도 요청자가 현재 호스트이고 상태가 `FinalResult`인지 확인한다. 경기 도중 복귀, 클라이언트의 복귀 요청, 중복 복귀를 거부한다.
- 레벨 이동이나 세션 재생성 없이 현재 연결, PlayerController, PlayerState, 닉네임, 호스트를 유지한다.
- 연결된 참가자 전원의 일반 걷기 캐릭터를 먼저 준비한 뒤 교체한다. 탈락자도 복귀한다.
- 관전 상태와 카메라, 전투 캐릭터, 이전 라운드 제거 타이머를 정리한다.
- `Waiting`으로 전환하면서 라운드 번호, 점수, 최종 순위, 승자, 참가자·생존자 목록을 초기화한다.
- 기존 대기 UI와 `AN_CF_STAND`/`AN_CF_WALK`를 사용하는 대기 AnimBP를 복원한다. 다시 시작하면 1R·0점으로 진행한다.
- 대기 중에는 신규 참가/재접속을 다시 허용한다. 1명만 남았다면 복귀는 가능하지만 경기 시작은 최소 2명 조건을 유지한다.

## 중단 및 오류 처리

- 인원이 부족하거나 다음 라운드를 준비하지 못하면 완료된 라운드 점수를 보존하고 결과 표시 후 최종 화면으로 이동한다. 최종 화면에 경기 조기 종료를 표시한다.
- 최초 1R 카운트다운 취소는 기존처럼 걷기 대기로 돌아간다. 2R 이후 카운트다운 취소는 최근 완료한 라운드의 점수로 최종 결과를 만든다.
- 최종 결과 예약 후 추가 퇴장이 발생해도 최종 화면 전환 시간을 계속 늦추지 않는다.
- 대기 캐릭터 설정이나 스폰 준비에 실패하면 기존 최종 결과와 캐릭터를 유지하고 호스트에게 오류를 표시한다. 성공하지 않은 복귀가 점수를 지우지 않는다.
- 호스트 나가기는 기존대로 방을 닫고 모든 클라이언트를 메인 메뉴로 돌려보낸다.

## 구현 위치

- `CFWaitingNetwork.h/.cpp`
  - `FCFFinalStanding`, `FinalStandings`: 복제되는 최종 순위 스냅샷.
  - `bFinalResultPending`: 라운드 결과 다음 목적지가 최종 결과인지 표시.
  - `ShowFinalResults()`: 서버에서 누적 순위·공동 순위 확정.
  - `TryReturnToWaiting()`: 호스트 권한 검사, 걷기 캐릭터 준비·교체, 경기 상태 초기화.
  - `RequestReturnToWaiting()` / 서버 RPC: UI 요청 전달.
- `CFMatchStatusWidget.h/.cpp`
  - 라운드 결과와 최종 결과 표시 전환, MVP 강조, 호스트 복귀 버튼, 오류 표시.
- 기존 블루프린트는 C++ 변경을 상속한다. 이번 단계에서 에셋 파일, 이동 수치, 전투 애니메이션, HP·피격 방향은 변경하지 않았다.

## 직접 확인

1. C++를 빌드하고 2~4명이 같은 방에 접속한다.
2. 4R까지 진행한다. 마지막 라운드 결과 6초 후 최종 결과가 표시돼야 한다.
3. 마지막 라운드 승자와 누적 점수 1위가 다르면 누적 1위가 MVP인지 확인한다. 총점 동률이면 공동 순위·공동 MVP를 확인한다.
4. 참가자에게는 복귀 버튼이 없고 호스트에게만 있는지 확인한다.
5. 호스트가 복귀하면 전원 같은 방의 걷기 대기로 돌아가야 한다. WASD로 걷고 키를 놓으면 서야 한다.
6. 다시 시작한다. 1R·0점에서 시작하고 자동 홉·닭싸움 입력이 다시 작동해야 한다.
7. 인원 부족으로 조기 종료된 경우에도 최종 결과에서 대기로 복귀할 수 있는지 확인한다. 새 참가자가 들어오면 다시 시작할 수 있어야 한다.

## 검증 기록

2026-10-02, UE 5.8.2 Win64 Development Editor 빌드 성공. 한 PC에서 독립 Unreal 프로세스를 실제 리슨 서버로 연결했다.

- 4인 두 경기 연속 진행, 단독/공동 MVP, 호스트 복귀, 점수 초기화, 권한·준비 실패 보호: 336개 검사 통과 (`full02`).
- 2인 무승부·공동 MVP, 관전자 전원 걷기 복귀, 새 경기 시작: 84개 검사 통과 (`draw01`).
- 3인 경기 중 기권·인원 부족 종료, 혼자 대기 복귀, 재접속 후 새 경기 시작: 53개 검사 통과 (`abort01`).
- 2R 카운트다운 취소 후 1R 점수로 최종 결과·대기 복귀: 38개 검사 통과 (`cancel01`).

총 511개 검사 통과. 최종 결과 및 대기 UI는 실제 렌더링으로도 확인했다. 테스트용 탈락은 서버에서 기존 `StartKnockdown()`을 호출했고, 대기 복귀 후 WASD 이동과 서기·걷기 애니메이션을 확인했다.

외부 인터넷/다른 PC, 패키징, 패킷 손실·지연 환경은 이번 검증에 포함하지 않았다. 엔진 선택적 메타데이터 사전 읽기를 우회하는 기존 임시 UBT 실행기를 사용했으며 엔진 설치 파일은 변경하지 않았다. 테스트 스크립트·로그·이미지는 작업 공간의 `tools/unreal/final_results_tests`에 보관한다.
