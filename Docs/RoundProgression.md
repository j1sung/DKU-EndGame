# 라운드 점수 및 자동 진행

최종 누적 순위·MVP와 같은 방 대기 복귀는 [FinalResults.md](FinalResults.md)에 정리되어 있다.

## 구현 범위

기존 대기 방에서 호스트가 시작하면 같은 아레나에서 아래 과정을 진행한다.

`3초 카운트다운 → 경기 → 순위·점수 결과 6초 → 전원 재생성 → 다음 라운드 카운트다운`

- 정원 4명, 시작·다음 라운드 최소 인원 2명.
- 1~4라운드까지 진행하며 점수는 누적한다.
- 4라운드 결과를 6초 표시한 뒤 `FinalResult`로 전환한다. 최종 누적 순위·MVP를 확인하고 호스트가 같은 방 대기로 복귀할 수 있다.
- 기존 균형 붕괴 또는 서버의 `StartKnockdown(Direction)` 호출로 탈락한다. 2026-10-02 dev 병합으로 친구의 캡슐 충돌 요청도 이 경로에 연결했다. HP·피해량·충격 방향 보정은 후속 범위이며 [Gameplay 충돌 설명](Gameplay/Overview.md#knockdown)을 참고한다.
- 라운드 구현 자체는 기존 이동·애니메이션을 사용한다. 이후 dev 병합에서 받은 충전 중 이동 입력 제한, 점프 수치·방향, AnimBP·테스트 맵 변경을 유지한다.

## 현재 점수 규칙

| 순위 | 이번 라운드 점수 |
| --- | --- |
| 1위 | +5 |
| 2위 | +3 |
| 3위 | +1 |
| 4위 | +0 |

2명 경기는 +5/+3, 3명 경기는 +5/+3/+1을 사용한다.

- 서버가 수락한 탈락 순서를 기준으로 마지막 생존자가 1위가 된다.
- 같은 **서버 프레임**에 탈락하면 공동 순위다. 예를 들어 4명 중 1명이 먼저 탈락하고 2명이 동시에 탈락하면 `1위 / 공동 2위 / 공동 2위 / 4위`이며 점수는 `5 / 3 / 3 / 0`이다. 프레임이 다른 요청을 묶는 별도 시간 허용치는 없다.
- 마지막 생존자들이 같은 프레임에 모두 탈락하면 승자 없는 무승부이며, 해당 플레이어들은 공동 1위로 각 +5점을 받는다. 무승부 점수를 0으로 하는 별도 규칙은 현재 적용하지 않았다.
- 경기 중 퇴장자는 해당 라운드 기권·0점 처리하고 순위 계산에서 제외한다. 이전 라운드 누적 점수는 보존한다.
- 카운트다운 중 퇴장자는 그 라운드 미참가 처리한다. 2명 이상이 남으면 남은 인원으로 진행하며 순위에 빈자리가 생기지 않는다.
- 이미 결과가 확정된 후 퇴장해도 확정된 점수는 바뀌지 않는다. UI에 `(퇴장)`과 흐린 행으로 표시한다.
- 이후 라운드에는 연결된 참가자만 재생성한다. 이전 퇴장자의 행은 남겨 누적 점수를 보존하고, 새 라운드는 미참가·0점으로 표시한다.

## 구현 위치

- `Source/DKUEndGame/Network/CFWaitingNetwork.h/.cpp`
  - `FCFPlayerRoundScore`: ID·닉네임·순위·이번 점수·누적 점수·연결/참가/기권 상태의 복제용 값 스냅샷.
  - `ACFWaitingGameState::Scoreboard`, `ScoredRound`: 최근 완료한 라운드의 결과. 다음 라운드 준비·경기 중에도 보존한다.
  - `NextRoundEndServerTime`, `GetResultSeconds()`: 서버 시간 기준 다음 라운드까지 남은 시간.
  - `ACFWaitingGameMode::ScoreRound()`: 서버만 집계. `ScoredRound` 검사로 중복 가산을 막는다. 점수표도 이 함수에서 정의한다.
  - `PrepareRound()`: 최초 시작과 다음 라운드 준비를 공통 처리한다. 관전자가 Pawn을 갖고 있지 않아도 참가할 수 있다.
  - `AdvanceRound()`: 결과 표시 시간이 끝나면 다음 라운드 준비. 4R 뒤에는 호출하지 않는다.
- `Source/DKUEndGame/UI/CFMatchStatusWidget.h/.cpp`
  - 승자/무승부와 `순위 / 플레이어 / 이번 라운드 / 누적` 표.
  - 공동 순위, 기권, 퇴장 표시, 다음 라운드까지 남은 시간 또는 중단 이유.
  - 기존 Esc 나가기 메뉴를 유지한다.

기존 `BP_CF_ArenaGameMode`는 C++ 구현을 상속하므로 별도 블루프린트 그래프 연결이 필요하지 않다. 결과 표시 시간은 해당 BP의 **Class Defaults → CF / Match → Round Result Duration**에서 조절한다. 기본 6초, 최소 3초이며 카운트다운은 기존 `Countdown Duration` 기본 3초다.

## 재시작과 예외 처리

- 스폰 위치는 기존 `ArenaSpawn` 태그의 PlayerStart를 사용한다.
- 모든 새 캐릭터 생성이 성공한 후 기존 캐릭터를 교체한다. 준비 실패 시 기존 캐릭터의 충돌을 복원하고 점수·라운드를 유지하며 중단 이유를 표시한다.
- 이전 라운드 캐릭터 제거 타이머를 취소하고, 남아 있는 이전 캐릭터를 정리한다. 새 캐릭터에 이전 타이머가 적용되지 않는다.
- 모든 참가자의 탈락·관전 상태를 해제하고 새 Pawn을 소유한다. 누적 점수를 유지하고 생존자 목록을 재구성한다.
- 카운트다운 중에는 이동·차징을 차단한다. 종료 후 원래 닭싸움 입력과 자동 홉을 사용한다.
- 결과 중 연결 인원이 2명 미만이 되면 다음 라운드 예약을 취소하고 결과 표시 후 최종 결과로 이동한다.
- 최초 1R 카운트다운 중 2명 미만이 되면 기존처럼 일반 걷기 대기로 돌아간다.
- 2R 이후 카운트다운 중 2명 미만이 되면 최근 완료된 라운드 결과로 돌아가 점수를 보존한 뒤 최종 결과로 이동한다. 미완료 라운드 점수는 부여하지 않는다.
- 호스트 퇴장 시 기존 연결 종료 처리로 참가자 모두 메인 메뉴에 복귀한다.

## 직접 테스트

1. 에디터를 닫은 상태에서 C++를 빌드하고, 메인 메뉴를 게임 실행본 2~4개로 연다.
2. 호스트에서 방 만들기, 나머지 창에서 접속한다. 같은 PC면 `127.0.0.1`을 사용한다.
3. 호스트의 경기 시작을 누른다. 3초 뒤 원래 자동 홉과 이동/차징이 가능한지 확인한다.
4. 한 참가자씩 WASD 한 방향을 계속 눌러 기존 균형 붕괴로 탈락시킨다. 마지막 1명이 남으면 결과 표와 점수를 확인한다.
5. 6초 후 탈락한 사람까지 새 경기 위치에서 다시 나타나고 관전 카메라가 해제되는지 확인한다.
6. 3초 카운트다운 중 조작은 막히고, 종료 후 다시 조작되는지 확인한다. 이전 점수는 다음 결과 표의 누적 점수에 더해져야 한다.
7. 4R까지 반복한다. 4R 결과 표시 후 최종 누적 순위·MVP가 나오며 5R로 넘어가지 않아야 한다. 호스트의 복귀 버튼으로 걷기 대기로 돌아가 새 경기를 시작한다.
8. 별도로 경기/결과/카운트다운 중 참가자가 나가는 경우, 기권·인원 부족·점수 보존을 확인한다.

## 라운드 진행 단계의 검증 기록

아래 기록은 최종 결과 기능 추가 전의 검증이다. 최신 전체 흐름 검증은 [FinalResults.md](FinalResults.md)를 참고한다.

2026-10-02, UE 5.8.2 / Win64 Development Editor 빌드 성공. 한 PC에서 독립 Unreal 프로세스를 실제 리슨 서버로 연결해 검증했다.

- 4인 1~4R 반복·공동 2위·누적 점수·UI·관전 해제: 394개 검사 통과 (`full02`).
- 2인 동시 최종 탈락·무승부·공동 1위·4R 반복: 173개 검사 통과 (`draw02`).
- 경기 중 기권·퇴장자 제외 재시작·결과 중 인원 부족: 108개 검사 통과 (`disconnect01`).
- 2R 카운트다운 취소·1R 확정 점수 보존: 59개 검사 통과 (`cancel01`).
- 1R 카운트다운 취소·걷기 대기 복귀: 12개 검사 통과 (`cancel_first01`).
- 4인 카운트다운 중 1명 퇴장·3인 4R 진행·순위와 누적 점수: 297개 검사 통과 (`countdown_leave01`).

총 1043개 검사 통과. 4인 결과 UI는 실제 렌더링으로도 확인했다. 탈락 주입은 테스트 스크립트가 서버에서 기존 `StartKnockdown()`을 호출했고, 카운트다운 입력 차단은 실제 W/마우스 입력으로 확인했다. 테스트용 피해/HP 기능은 제품 코드에 추가하지 않았다.

빌드는 이전 검증과 같은 임시 UBT 실행기를 사용해 선택적 메타데이터 사전 읽기 정지만 우회했다. 설치된 엔진 파일은 수정하지 않았다. 기존 MSVC 권장 버전 및 엔진 API 사용 중단 예정 경고 외 컴파일 오류는 없었다.

외부 인터넷/서로 다른 PC, 패키징 실행본, 패킷 지연·손실 환경은 이번 검증에 포함하지 않았다. 테스트 스크립트와 로그는 작업 공간의 `tools/unreal/round_progression_tests`에 보관한다.
