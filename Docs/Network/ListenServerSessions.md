# LAN 리슨 서버와 연결 종료

> 최근 기능 변경: 2026-10-02 · @KyuminChung (`c8a7452`, `99aeaf1`); 초기 세션·대기 구현: Git 작성자 정규민 (`d13290b`)

관련 개요: [카테고리 개요](Overview.md)

## 현재 범위

`OnlineSubsystemNull` 기반 LAN 방 생성·검색·참가, 직접 IPv4 접속, 참가자 퇴장, 호스트 정상 종료 및 연결 오류 복구를 구현했습니다. 정원은 호스트 포함 4명이며, 최소 시작 인원은 2명입니다. 서버가 직접 정원을 검사하므로 IP로 접속해도 정원을 넘을 수 없습니다.

방을 열면 기존 `Lvl_CF_Arena`에서 대기 UI와 일반 서기·걷기 캐릭터를 사용합니다. 참가자 이름과 호스트 표시는 복제된 PlayerState/GameState로 표시합니다. 2명 이상이면 호스트가 시작할 수 있습니다. Waiting → Countdown → Playing, 전투 캐릭터/입력 전환과 경기 중 나가기를 연결했습니다. 상세 내용은 [경기 시작 문서](../MatchStart.md)를 참고하세요. 탈락 후 제거·고정 관전·4라운드 점수·최종 결과·같은 방 대기 복귀도 연결되어 있습니다. [라운드 진행](../RoundProgression.md), [최종 결과](../FinalResults.md)를 참고하세요. HP·피해량은 후속 범위입니다.

Steam/EOS, 인터넷 방 검색, 초대, NAT 통과 및 호스트 마이그레이션은 포함하지 않습니다. 서로 다른 집에서의 접속은 별도 온라인 서비스/네트워크 구성이 필요합니다.

## 구성

| 코드 | 책임 |
| --- | --- |
| `CFSessionSubsystem` | GameInstance 수명의 로컬 세션 관리자. 생성·검색·참가·나가기, 비동기 콜백 정리, 타임아웃, Network/Travel Failure 처리 |
| `CFWaitingGameMode` | 서버 정원 4명 강제, 호스트 지정, 시작 승인·스폰·카운트다운, 경기 중 신규 참가 거절 |
| `CFWaitingGameState` | 호스트 PlayerState, 정원, 방 종료 여부, 경기 상태·라운드·참가자·생존자·카운트다운 시각 복제 |
| `CFWaitingPlayerController` | 닉네임·시작 요청을 서버에 전달, UI·입력 전환, 호스트 종료 통지 수신 |
| `CFMainMenuWidget` | 기존 Designer UI에 네트워크 동작 연결, 방 목록·중복 클릭 방지·오류 안내 |
| `CFWaitingRoomWidget` | 실제 참가자 목록과 역할 표시, 나가기 요청. 화면 그리기와 독립적인 월드 타이머로 목록 갱신 |

`BP_CF_ArenaController`와 `BP_CF_ArenaGameMode`는 각각 새 C++ 컨트롤러/게임모드를 상속합니다. 기존 `BP_CF_WaitingCharacter`, `IMC_CF_Waiting`, `ABP_CF_Waiting`을 유지합니다. 경기 시작 확장에서 경기장 스폰을 4곳으로 늘렸고, 전투 캐릭터에 입력 잠금과 서버 상태 복제를 추가했습니다. 기존 애니메이션 에셋과 이동·기울기 수치는 유지합니다.

## 종료와 실패 동작

- **참가자 나가기**: 로컬 세션을 정리하고 메뉴로 이동합니다. 호스트 방은 유지되고 참가자 목록에서 빠집니다.
- **호스트 나가기**: 신규 참가를 차단하고 연결된 클라이언트에 Reliable RPC로 종료를 알립니다. 짧은 전송 유예 후 호스트 세션과 리슨 월드를 종료합니다. 클라이언트는 ‘호스트가 방을 종료했습니다’ 안내와 함께 메뉴로 돌아옵니다.
- **호스트 강제 종료/연결 손실**: 연결 실패 이벤트에서 세션을 정리하고 원인을 메뉴에 표시합니다. 이후 새 방 생성/재접속이 가능합니다.
- **연결 시도 시간 초과**: 대기 중인 PendingNetGame을 명시적으로 취소하고 메뉴를 다시 엽니다. 이전 연결 시도가 남아 입력이나 재접속을 막지 않습니다.
- **중복 입력**: Idle 상태에서만 생성·검색·참가를 허용합니다. 검색 중 취소만 별도로 허용합니다. 종료 중 추가 종료 요청은 무시합니다.

## 설정

- `DKUEndGame.uproject`: `OnlineSubsystemNull` 활성화.
- `DKUEndGame.Build.cs`: `OnlineSubsystem`, `OnlineSubsystemUtils`, `SlateCore` 의존성 추가.
- `DefaultEngine.ini`: 기본 온라인 서비스 `NULL`, 초기 연결 제한 15초 / 연결 손실 제한 10초.
- 세션 관리자: 생성 15초, 검색 10초, 세션 참가 20초, 맵·호스트 연결 25~30초, 세션 정리 5초의 최대 대기 시간.
- 정원: `CFSessionSubsystem::RoomCapacity`.

## 직접 확인

1. 프로젝트 C++를 빌드합니다.
2. 같은 LAN의 두 PC에서 메뉴로 시작합니다. 서로 다른 닉네임을 입력합니다.
3. 첫 PC에서 **방 만들기**, 두 번째에서 **참가하기 → 방 선택 → 참가**.
4. 양쪽에서 `2 / 4`, 같은 이름들, 호스트 배지 하나, 서로의 이동·서기·걷기를 확인합니다.
5. 참가자 **나가기** 후 호스트가 계속 남는지 확인하고 다시 참가합니다.
6. 호스트 **나가기** 후 양쪽 메뉴 복귀 및 참가자의 종료 안내를 확인합니다.
7. 다시 연결한 뒤 호스트 실행본을 강제 종료해 연결 손실 안내와 메뉴 복귀를 확인합니다.

같은 PC에서는 게임을 독립된 두 프로세스로 실행해도 됩니다. 실제 메뉴 흐름 테스트는 두 실행본 모두 메뉴에서 시작해야 합니다. PIE의 자동 ‘Play As Client’ 연결만으로는 방 생성·검색 UI를 검증할 수 없습니다.

UE 5.8은 PIE에서 네트워크 타임아웃을 기본적으로 끕니다. 따라서 호스트 강제 종료 시 자동 복귀 시간은 일반 게임 실행본에서 확인하는 것이 좋습니다. 자동 오류 테스트에서는 편집기 전용 도구로 이 제한만 해제하고 게임 설정의 타임아웃을 사용했습니다.

방이 검색되지 않으면 동일 네트워크인지 확인한 뒤 호스트의 로컬 IPv4로 직접 접속해 보세요. 서로 다른 PC의 방화벽/공유기 상태는 이번 로컬 테스트 범위에 포함되지 않습니다. 패키징할 때는 메뉴와 아레나 두 맵이 빌드에 포함되는지도 확인하세요.

## 기존 검증 기록

아래는 기존 문서에 남아 있던 결과이며 이번 문서 정리에서 재실행한 결과가 아니다.

아래는 2026-09-29 당시 2명 정원 구현의 검증 기록입니다. 현재 4명 확장과 경기 시작 검증은 [경기 시작 문서](../MatchStart.md)에 정리합니다.

- 프로젝트 C++ Editor 빌드 성공. 관련 Blueprint 5개 컴파일 및 부모 클래스·기본 Pawn·입력 매핑 확인.
- 독립된 호스트/클라이언트 프로세스로 정상 흐름 47개 검사 통과: 실제 LAN 검색, 참가와 IP 재접속, 이름·정원·호스트 배지 복제, 양쪽 이동과 Walk 평가, 참가자 퇴장 후 방 유지, 호스트 종료 시 모두 메뉴 복귀, 이전 참가자의 새 방 생성, 검색 취소 및 모달 입력 잠금.
- 별도 오류 시나리오에서 클라이언트 14개 + 추가 참가자 12개 검사 통과: 호스트 프로세스를 강제 종료한 후 오류 안내·메뉴 복귀·새 방 생성, 잘못된 IP 거절, 세 번째 직접 접속의 정원 초과 거절, 응답 없는 주소의 연결 시간 초과 및 메뉴 입력 복구.
- 실제 렌더링 화면에서 검색 목록, 2인 대기 UI, 호스트 종료 안내 표시 확인.
- 경기장 맵, 공용 IMC_Default, ABP_Chicken, ABP_CF_Waiting의 SHA-256이 작업 전과 동일함을 확인.

네트워크 검증은 한 PC에서 분리한 실제 UE 프로세스 사이의 통신입니다. 두 물리 PC, 인터넷, 패키징 실행본 테스트는 아직 수행하지 않았습니다. 테스트용 편집기 도구는 게임 소스/프로젝트에 의존성으로 추가하지 않았습니다.
