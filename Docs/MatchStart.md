# 경기 시작과 상태 관리

현재는 탈락·관전·라운드 결과까지 연결되어 있다. 최신 흐름과 테스트 방법은 [RoundEnd.md](RoundEnd.md)를 참고한다. 아래는 경기 시작 기반을 만들었을 때의 구현 기록이다.

## 경기 시작 기반 구현 범위

- 호스트 포함 최대 4명, 최소 시작 인원 2명.
- 기존 아레나 `Lvl_CF_Arena` 안에서 Waiting → Countdown → Playing 전환.
- 같은 방의 호스트만 시작 가능. UI 표시와 별도로 서버가 권한·인원·상태를 검사한다.
- 시작 시 원본 `BP_ChickenCharacter`로 교체하고 태그 `ArenaSpawn`인 PlayerStart에 한 명씩 배치한다.
- 경기 스폰은 `ArenaSpawn_01`부터 `ArenaSpawn_04`까지 4곳이다.
- 서버 시간 기준 3초 카운트다운 동안 이동, 기울기, 차징, 자동 홉을 잠근다. 종료 후 기존 조작을 허용한다.
- 대기 UI를 제거하고 라운드·생존 인원·카운트다운 HUD를 표시한다.
- 대기 중에는 일반 서기·걷기를 유지한다. 캐릭터 교체에 맞춰 대기/전투 입력 컨텍스트를 전환한다.
- 경기 중 Esc를 누르면 마우스와 방 나가기 버튼을 사용할 수 있다. 호스트가 나가면 참가자도 메뉴로 돌아온다.

## 상태와 책임

| 구성 | 책임 |
| --- | --- |
| `ACFWaitingGameMode` | 서버 시작 승인, 네 곳 스폰 검증, Pawn 교체, 카운트다운 타이머, 참가자 퇴장 및 시작 취소 |
| `ACFWaitingGameState` | Phase, 현재/총 라운드, 카운트다운 종료 서버 시각, 이번 라운드 참가자·생존자 목록 복제 |
| `ACFWaitingPlayerController` | 시작 요청 RPC, 로컬 UI 수명과 입력 컨텍스트, Esc 메뉴 |
| `UCFWaitingRoomWidget` | 참가자 목록, 2명 이상일 때 호스트 시작 버튼 활성화, 시작 요청 |
| `UCFMatchStatusWidget` | 초기 경기 HUD. 라운드/생존 인원, 카운트다운, 나가기 표시 |
| `AChickenCharacter` | 서버의 경기 입력 잠금, 기울기/차징 입력 전달, 서버 자동 홉/차징 점프와 애니메이션 상태 복제 |

`ECFMatchPhase`에는 Waiting, Countdown, Playing, RoundResult, FinalResult가 있다. **이번에 실제 연결한 전환은 Waiting → Countdown → Playing까지**다. 결과 상태는 후속 구현용이며 자동 승자 결정·점수 계산·다음 라운드 진행은 아직 실행하지 않는다.

현재 라운드는 대기에서 0, 경기 시작 시 1이며 총 라운드는 기획 기준 4다. 로비의 연결 명단은 기존 PlayerArray를 사용하고 Participants/AlivePlayers는 시작 시점에 확정한 라운드 명단이다. PlayerState를 저장하므로 Pawn 교체와 분리된다. 기존 균형 실패로 넘어질 때 서버가 AlivePlayers에서 제외한다. 나간 플레이어는 라운드 명단에서도 제거한다.

## 입력 및 네트워크

- 대기: `IMC_CF_Waiting`, 일반 WASD 걷기.
- 경기: `IMC_Default` 및 `IMC_MouseLook`. 기존 닭싸움 WASD 이동·기울기와 왼쪽 마우스 차징/해제를 사용한다.
- 대기 캐릭터의 일반 이동은 기존 CharacterMovement 경로를 사용한다. 전투 이동도 엔진의 캐릭터 이동 복제를 사용한다.
- 전투 기울기 입력은 소유 클라이언트에서 서버로 전달한다. 균형 누적, 차징 값, 점프 및 넘어짐 판정은 서버에서 처리한다. 관련 상태를 복제해 각 AnimBP가 표시한다.
- 기존 기울기 수치, 이동 수치, 차징 수치, 기본 동작/4방향 넘어짐 AnimBP는 유지한다.
- 기본 입력 잠금 값은 열림이므로 단독 `Test_CF_Knockdown`은 기존처럼 사용할 수 있다. 아레나 게임모드가 카운트다운을 위해 잠그고 해제한다.

## 예외 처리

- 1명 시작, 참가자의 임의 시작 RPC, 카운트다운/경기 중 재시작 요청을 서버에서 거부한다.
- 스폰 또는 전투 클래스 준비에 실패하면 기존 대기 Pawn을 유지하고 안내한다. 모든 새 Pawn을 준비한 뒤 일괄 교체한다.
- 카운트다운 중 2명 미만이 되면 타이머와 라운드 명단을 정리하고 남은 플레이어를 걷기 대기로 복귀시킨다.
- 카운트다운과 경기 중 신규 접속은 거부하고 메뉴에서 이유를 안내한다. 경기 도중 참가 정책은 향후 확장할 수 있다.
- 5번째 접속은 정원 초과로 거부한다. 직접 IP 접속에도 동일하게 적용한다.
- 경기 중 누군가 나가면 명단을 갱신한다. 자동 라운드 종료는 후속 승자 판정 단계에서 추가한다.

## 직접 테스트

1. C++를 빌드한 뒤 같은 프로젝트의 게임 실행본을 두 개 켜서 `Lvl_CF_MainMenu`로 시작한다.
2. 첫 창에서 닉네임 입력 → 방 만들기, 두 번째 창에서 닉네임 입력 → 방 접속.
3. 대기 UI의 `참가자 2 / 4`와 호스트의 활성화된 경기 시작 버튼을 확인한다. 대기 중에는 WASD로 걷는다.
4. 호스트가 경기 시작을 누르면 양쪽 모두 닭싸움 자세로 바뀌고 3·2·1 카운트다운이 나온다. 이때 WASD와 차징을 눌러도 움직이거나 충전되지 않아야 한다.
5. 카운트다운 후 WASD와 왼쪽 마우스 차징/해제, 자동 홉을 확인한다. 라운드는 `ROUND 1 / 4`로 표시된다.
6. Esc → 방 나가기. 호스트가 나갔다면 다른 창도 메인 메뉴로 돌아오는지 확인한다.
7. 별도로 카운트다운 도중 참가자가 나가면 호스트가 걷기 대기로 돌아오는지 확인한다.
8. 실행본 4개로 같은 방에 입장해 시작한다. 다섯 번째 창의 입장은 거부돼야 한다.

정원은 `CFSessionSubsystem::RoomCapacity`, 최소 인원은 `CFWaitingGameState::MinimumPlayers`, 카운트다운 길이와 전투 클래스는 `BP_CF_ArenaGameMode`의 Class Defaults → CF / Match에서 확인한다.

## 다음 범위

피격 방향/HP 연동, 넘어짐 완료 후 캐릭터 제거, 승자 클로즈업, 라운드별 점수와 누적 점수, 2~4R 및 최종 결과·같은 방 로비 복귀. 탈락 후 링 밖 걷기 캐릭터는 생성하지 않는다. 임시 관전 카메라는 캐릭터 제거 단계에서 연결한다.

## 검증 기록 — 2026-10-02

- UE 5.8.2 Development Editor / Win64 C++ 빌드 성공.
- 한 PC에서 독립 UE 프로세스를 실행하고 실제 리슨 서버 연결로 검증했다. 2명 시나리오 61개, 4명 시나리오 77개 검사 통과.
- 호스트만 시작 가능, 1명 시작 거부, 2~4명 시작, 5번째 입장 거부, 경기 시작 후 신규 입장 거부를 확인했다.
- 대기 Pawn → 원본 전투 Pawn, 서로 다른 스폰, 참가자/생존자 복제, 3초 입력 잠금·해제, 원본 AnimBP, 이동·차징 점프와 원격 차징 상태를 확인했다.
- 초기 클라이언트 복제가 BeginPlay보다 먼저 발생해도 모델 기본 회전이 유지되는지 확인했다.
- 2명 카운트다운 중 참가자 퇴장 → 호스트 걷기 대기 복귀 → 재접속·재시작과, 경기 중 Esc 나가기 → 전체 메인 메뉴 복귀를 확인했다.
- 기존 단독 Test_CF_Knockdown 회귀 검사 73개 통과: 기존 이동·기울기 누적/회복·차징·자동 홉·4방향 넘어짐·R 재생성 유지.
- 실제 서로 다른 PC/외부 인터넷 연결, 패키징 실행본, 패킷 지연/손실 환경은 이번 검증에 포함하지 않았다.
