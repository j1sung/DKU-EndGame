# 언리얼 EOS 자동 매칭 클라이언트 인계서

> 대상: 게임 화면·게임플레이 담당자와 EOS·백엔드 통합 담당자
>
> 기준: 2026-11-03, 개발 환경의 `standard` 4인 모드 / 클라이언트 버전 `0.1.0`
>
> 상세 API 계약: [Unreal 매칭·매치 연동 계약](unreal-matchmaking-ticket-api.md)

## 1. 목표와 현재 상태

플레이어가 Epic 로그인 후 게임 전용 닉네임을 확인하고, 메인 화면에서 매칭을 시작해 다른 세 명과 같은 경기 맵에 들어가 플레이한 뒤 결과 화면을 보는 흐름을 완성한다.

개발 AWS에서는 서로 다른 Epic 계정 네 개로 인증, 4인 배정, 배정 전 취소, 이탈, 시간 초과를 검증했다. **EOS 세션 생성·참가·게임 시작·종료는 테스트 도구가 API에 모의 보고한 결과**다. 패키징된 언리얼 빌드의 실제 EOS 세션과 4인 동시 플레이는 아직 확인하지 않았다.

현재 `dev`의 LAN 방 생성·검색, 2명 이상 수동 시작, 같은 방 대기 복귀는 게임플레이 테스트 구현이다. **제품 방향은 EOS 기반 자동 4인 매칭**이며, 기존 LAN 화면·세션 경로가 자동 매칭에 이미 연결됐다는 뜻은 아니다. 현재 코드와 에셋은 [UI 개요](../UI/Overview.md), [Network 개요](../Network/Overview.md), [경기 결과](../FinalResults.md)를 기준으로 확인한다.

2026-11-05 CKM 작업에는 기존 Figma 진입 UI에 `UCFEntrySubsystem`을 연결했다. Epic Account Portal·Connect 인증, 프로필 조회·최초 닉네임 등록과 `L_Lobby_Playground` 이동 코드를 구현했다. **클라이언트 EOS 설정·권한은 미구성이며 실계정 인증·인증된 HTTP는 미검증이다.** 통합 담당은 [Entry 설정·확인 항목](../Network/LoginEntry.md)과 [메인 메뉴 이벤트 계약](../UI/MainMenu.md#상태와-통합-연결)을 기준으로 현재 제공자를 재사용한다. Figma의 타이틀 `게임 시작`은 인증 진입이며, 아래 메인/매칭 버튼은 별도 연습 로비 화면에서의 매칭 시작을 뜻한다.

## 2. 담당 범위

| 영역 | 통합 담당 | 게임 클라이언트 담당 |
|---|---|---|
| Epic/EOS 로그인, Connect ID Token 갱신, 백엔드 API 호출 및 오류 변환 | 구현·제공 | 화면에 상태와 오류 표시 |
| EOS 세션 생성·참가, 리슨 서버 연결, 매치 상태 보고 | 구현·제공 | 맵 전환과 게임 시작·종료 이벤트를 연결 |
| 로그인·닉네임·매칭·연결·결과 화면 | 화면에 필요한 상태와 동작 인터페이스 제공 | UI 제작, 버튼 연결, 로딩·오류 상태 표현 |
| 캐릭터, 경기 규칙, 승패 판정, 게임 내 네트워크 동기화 | 통합 시 연결 지원 | 기존 LAN 구현을 EOS 매치 흐름에 맞게 조정하고 4인 플레이 검증 |
| 패키징된 Windows 빌드의 4인 통합 검증 | 함께 수행 | 함께 수행 |

게임 담당자는 API 요청 형식이나 EOS 인증을 화면 코드에 중복 구현하지 않는다. 통합 담당이 제공할 **클라이언트 상태·동작 인터페이스**를 UI와 게임 흐름에 연결한다. 타이틀 인증·프로필·로비 진입에는 `UCFFrontendSubsystem`을 연결점으로 사용하며, 자동 매칭 화면에는 `UCFLobbySubsystem`의 요청/응답 인터페이스를 추가했으며 [로비 연결 계약](../UI/Lobby.md#매칭-통합-연결)을 사용한다. 인증·프로필 HTTP 제공자는 Entry에 추가했고, 매칭 HTTP 요청·대기·취소·배정 조회는 [CFMatchmakingSubsystem](../Network/Matchmaking.md)에 연결했다. 실계정 API 검증과 실제 EOS 세션 동작은 후속 통합 범위다. `dev`에는 `CFMainMenuWidget`, `CFWaitingRoomWidget`, `CFMatchStatusWidget`과 LAN 세션 기반 게임 흐름이 있으므로 이를 재사용·수정할 지점을 함께 정한다. EOS 로그인 코드는 Editor 빌드·응답/화면/맵 이동 검사까지 확인했다. 실계정 로그인과 자동 매칭·실제 EOS 세션 연결의 완료를 의미하지 않는다.

## 3. 화면별 구현 항목

| 화면/상태 | 필요한 UI 요소와 동작 | 전환 기준 |
|---|---|---|
| 실행·로그인 | 로그인 진행 표시, 실패 안내, 다시 시도 버튼. 토큰·계정 비밀값은 표시하지 않음 | 인증 및 프로필 조회 성공 시 메인 화면 또는 닉네임 등록 화면 |
| 최초 닉네임 등록 | 입력 칸, 2~16자 안내, 사용 불가·중복·이미 등록된 이름 오류, 등록 중 버튼 중복 클릭 방지. 한글 완성형·영문·숫자·내부 공백 지원 | 최초 등록 성공 후 메인 화면. 첫 버전에서 닉네임 변경 불가 |
| 메인 | 내 닉네임, `게임 시작` 버튼, 로그인·서버 연결 상태 | 매칭 요청 성공 시 대기 화면. 이미 활성 상태이면 현재 상태를 복구해 해당 화면으로 이동 |
| 매칭 대기 | `4인 매칭 중`, 남은 대기 시간, `매칭 취소` 버튼, 통신 재시도 표시 | 대기 최대 3분. `WAITING` 중 취소 성공 시 메인으로 이동. `ASSIGNED`가 되면 취소 비활성화 후 세션 준비로 이동 |
| 세션 준비·연결 | `상대와 연결 중` 등의 단계 표시, 현재 단계의 최대 60초 기한에 맞는 진행 표시. 이때 매칭 취소 버튼 없음 | 호스트의 세션 생성, 네 명의 실제 참가, 시작 보고가 끝나면 경기 맵으로 이동. 실패·만료 시 안내 화면 |
| 경기 | 경기 규칙에 필요한 HUD, 네 플레이어 식별 표시, 시간·점수·생존 상태 등 실제 게임 규칙에 맞는 정보, 일시정지/설정과 나가기 동작 | 리슨 서버와 참가자 모두 같은 맵에서 플레이. 결과 확정 또는 이탈·연결 실패 시 종료 흐름 |
| 결과·실패 | 승패/무승부 등 실제 규칙의 결과, 실패 이유, `메인으로`와 `다시 매칭` 진입점 | 서버 매치가 `FINISHED`·`FAILED`·`EXPIRED`로 정리된 뒤 새 매칭 가능. 자동 재매칭 없음 |

화면 문구와 배치는 제안이며 게임의 아트·UX 기준에 맞게 조정할 수 있다. **`READY_TO_START`는 네 명의 세션 참가 보고가 완료됐다는 서버 상태**다. 별도의 플레이어 `준비 완료` 버튼이 필요한 설계는 현재 계약에 없다.

## 4. 사용자가 보는 흐름과 경계 상황

1. 로그인 후 프로필을 조회한다. 닉네임이 없으면 등록 화면을 먼저 보여준다.
2. `게임 시작`을 한 번 누르면 매칭 요청을 보낸다. 대기 화면에서는 약 2초 간격으로 현재 상태를 확인한다. 서버의 `Retry-After` 지시가 있으면 우선하며, 반복되는 통신 오류에서는 조회 간격을 최대 5초까지 늘린다.
3. `매칭 취소`는 **4명 배정 전 `WAITING` 상태에서만** 가능하다. 취소하면 본인만 대기열에서 빠지고 다른 사용자는 계속 기다린다. 취소와 배정이 동시에 일어나 배정이 먼저 확정됐다면 매치 연결 흐름으로 이동한다.
4. `ASSIGNED` 이후 서버가 지정한 호스트가 EOS 세션을 만들고, 다른 세 명이 참가한다. 실제 세션 동작이 성공한 뒤 통합 계층이 서버에 해당 단계를 보고한다. 각 준비 단계의 60초는 최대 시간이며 성공하면 바로 다음 단계로 간다.
5. 네 명의 참가가 확인되면 호스트가 시작을 보고하고 실제 경기로 들어간다. 경기는 시작 후 최대 30분으로 제한된다. 경기 완료는 호스트가 보고한다.
6. 사용자가 게임 도중 나가거나 세션 연결에 실패한 경우, 화면과 게임 상태를 정리하고 통합 계층의 이탈·실패 처리로 연결한다. 첫 버전에서 한 명의 이탈은 매치 전체를 `FAILED`로 끝낸다. 재접속과 호스트 교체는 현재 범위에 없다.

### UI에서 반드시 처리할 예외

- 매칭 요청 중 버튼을 반복해서 눌러도 여러 요청이 생성되지 않게 한다. 응답이 늦게 와도 이미 취소된 화면이 다시 대기 화면으로 돌아가지 않아야 한다.
- 앱 재실행·화면 복귀 시 현재 티켓 또는 매치를 먼저 조회해 대기·준비 화면을 복원한다. `ALREADY_ACTIVE`는 새 매칭을 반복 요청하지 말고 현재 상태를 조회한다. 경기 중 재접속은 첫 버전에서 지원하지 않으므로 이전 경기로 다시 들어갈 수 있다고 안내하지 않는다.
- `NICKNAME_REQUIRED`는 등록 화면, `CLIENT_VERSION_UNSUPPORTED`는 업데이트 안내로 연결한다.
- 통신 오류는 즉시 매칭 실패로 단정하지 않는다. 현재 상태를 다시 확인하고, 복구 불가할 때만 재시도 안내를 보여준다.
- 서버가 `FAILED` 또는 `EXPIRED`를 반환하면 준비·경기 UI를 닫고 결과/실패 안내로 이동한다. 기한이 지났어도 서버 정리가 약간 늦을 수 있으므로 화면 타이머만으로 새 매칭을 시작하지 않는다.

## 5. 실제 게임플레이 화면과 네트워크 고려 사항

- **식별:** 다른 플레이어 위 표시, HUD, 결과 화면에 게임 전용 닉네임을 사용한다. EOS PUID나 토큰을 사용자에게 보여주지 않는다. 한글 닉네임의 글꼴·줄바꿈·좁은 화면 표시를 확인한다.
- **공정한 시작:** 네 명이 실제 경기 맵에 연결되고 플레이 가능한 상태가 되기 전에는 조작·카운트다운을 시작하지 않는다. 맵 로딩과 스폰 완료 시점은 게임 로직과 통합 계층이 합의해 연결한다.
- **권한:** 리슨 서버가 경기 규칙과 승패를 판정하고 결과를 다른 클라이언트에 동기화한다. 각 화면의 점수·남은 시간·생존 여부는 경기 중 언리얼 네트워크 상태를 기준으로 표시한다. 백엔드 매치 API는 세션과 경기의 큰 단계 기록에 사용한다.
- **이탈:** `나가기`를 누르면 현재 매치가 네 명 모두에게 종료될 수 있음을 확인 문구로 알린다. 실제 연결 끊김과 자발적 나가기를 게임 화면에서 구분해 안내하되, 서버 상태는 통합 계층과 일치시킨다.
- **결과:** 승패 판정·결과 HUD·결과 화면 전환을 한 번만 실행하고, 호스트의 종료 보고와 충돌하지 않게 한다. 결과 정보 자체의 저장·전적 기능은 현재 백엔드 범위가 아니다.
- **접근성:** 긴 대기와 연결 중에는 진행 상태를 텍스트로도 알리고, 버튼 비활성화 이유와 오류 후 가능한 다음 동작을 명확히 보여준다.

## 6. 통합 담당이 제공할 연결점

게임 담당자가 UI를 구현할 수 있도록 통합 담당은 다음 이벤트와 동작을 언리얼에서 호출 가능한 형태로 제공한다. 이름은 예시이며 최종 API 클래스명은 구현 시 정한다.

| 게임/UI가 받는 상태 | 게임/UI가 호출하는 동작 |
|---|---|
| 로그인·프로필 상태와 내 닉네임 | 로그인 재시도, 닉네임 등록 |
| 대기 중 티켓, 남은 시간, 매칭 오류 | 매칭 시작, 배정 전 취소 |
| 배정된 `matchId`, 호스트 여부, 세션 연결 단계 | 연결 화면 열기, 맵 로딩 완료·실제 참가 완료 알림 |
| 경기 시작 가능, 매치 종료·실패 상태 | 게임 시작 준비 완료, 경기 종료·나가기 알림 |

인증 토큰, AWS API 주소, 멱등성 키, `hostAttempt`, 폴링·재시도는 통합 계층이 관리한다. 게임/UI는 이 내부 값을 직접 저장하거나 화면에 표시하지 않는다. 세부 HTTP 경로와 JSON은 [API 계약](unreal-matchmaking-ticket-api.md)을 따른다.

## 7. 작업 순서와 완료 기준

1. **화면 정리:** 기존 메인·대기·경기·결과 위젯을 확인하고 로그인/닉네임/자동 매칭 대기/연결 화면과 상태 전환을 추가·수정한다. 임시 상태로도 전체 화면 흐름을 시연할 수 있게 한다.
2. **통합 연결:** 제공된 상태·동작 인터페이스에 버튼과 화면 전환을 연결한다. 취소와 배정 경합, 오류 후 복원까지 확인한다.
3. **게임플레이 연결:** 기존 4명 스폰, 캐릭터 조작, 경기 규칙, 서버 권한 승패 판정과 HUD 동기화를 자동 배정·EOS 참가 흐름에서 재검증하고 필요한 부분을 조정한다.
4. **실제 세션 테스트:** Windows 패키징 빌드 네 개를 서로 다른 Epic 계정으로 실행해 매칭 → EOS 세션 생성 → 네 명 참가 → 같은 맵에서 플레이 → 결과 → 새 매칭 가능까지 확인한다.

완료를 판단할 때는 아래를 확인한다.

- [ ] 닉네임이 없는 계정과 이미 등록된 계정 모두 올바른 화면으로 간다.
- [ ] 취소는 `WAITING`에서만 가능하고, 다른 참가자의 대기를 끝내지 않는다.
- [ ] 네 계정 모두 같은 매치와 게임 맵에 들어가며 닉네임이 올바르게 보인다.
- [ ] 호스트와 참가자 화면에서 경기 시작·점수·승패가 일치한다.
- [ ] 한 명 이탈, 세션 실패, 시간 초과 후 모두에게 명확한 안내가 보이고 새 매칭이 가능하다.
- [ ] 실제 EOS 세션·4인 플레이 테스트 결과를 기록한다. 개발 AWS의 기존 API 모의 보고 성공을 이 항목의 완료로 대신하지 않는다.

## 8. EOS 연동 시 확정할 게임 흐름

현재 LAN 테스트 흐름에는 4라운드, 점수·MVP 결과, 호스트의 같은 방 대기 복귀와 3초 시작 카운트다운이 있다. 이 기능을 EOS 자동 매칭 뒤에도 어떻게 사용할지 통합 담당과 게임 담당자가 정해 화면과 네트워크 구현에 반영한다. 아래 항목은 **백엔드 API가 자동으로 결정하지 않는다.**

- 기존 4라운드·공동 순위·MVP 결과를 자동 매칭 경기의 완료 조건으로 사용할지
- 기존 점수·생존 인원·카운트다운 HUD 중 유지하거나 바꿀 항목
- 기존 아레나 스폰과 3초 카운트다운을 EOS 참가 완료 시점에 어떻게 연결할지
- 현재 같은 방 대기 복귀를 종료하고 메인 화면의 새 자동 매칭 진입으로 바꿀지
- 나가기 확인 문구와 연결 끊김 시 사용자 안내 문구

역할 분담의 원문은 [백엔드·인프라 공통 가이드](../../Backend-Infra/GAME_BACKEND_GUIDE.md)를 따른다. 이 문서는 게임 담당자에게 전달할 실행 항목이며, API 계약을 변경하지 않는다.
