# 경기 식별·랜덤 맵 이동 구현 계획

> 실행: superpowers:executing-plans. 사용자 지정 `codex/match-presentation-and-round-travel` 체크아웃에서 진행한다. 새 worktree/푸시는 요청 범위에 포함하지 않는다.

**목표:** 머리 위 한글 닉네임, 중복 없는 임의 4색, 네 맵 무중복 랜덤 순서, 경기 전 걷기 제거, 각자 결과 확인 후 연습 로비 복귀.

**구조:** 서버 GameInstance에 맵 순서·색상·점수 이전 상태를 보관한다. EOS 세션은 유지하며 ServerTravel/Seamless Travel로 다음 맵에 이동한다. 복제 GameState는 현재 라운드와 준비 화면 상태를 제공한다. 결과는 reliable RPC로 각 클라이언트 GI에 복사하고 수신 확인 후 finished를 보고한다. 결과 화면은 네트워크 월드와 독립적으로 유지한다.

**기술:** UE5.8, 기존 EOS/Sessions/HTTP, native UMG와 캐릭터 ActorComponent, 에디터 Python 머티리얼 도구.

**명세 근거:** 이번 대화의 네 QA 항목과 ‘각자 결과 확인 후 연습 로비 복귀’ 선택. 기존 [세션 계약](../../unreal-matchmaking-ticket-api.md), [경기 코드](../../../Gameplay/Overview.md#match)를 유지한다.

## 고정 조건

- 네 실제 맵을 서버가 경기마다 한 번 섞으며 각각 한 번만 사용한다. 라운드 번호와 맵 번호는 다르다.
- 최초 joined/started만 API에 보고하며 맵 이동마다 새 세션이나 매치를 만들지 않는다. 중간 이탈은 기존 전체 실패 정책을 유지한다.
- 색상은 구분 가능한 4색을 무중복 배정하고 경기 중 유지한다. 닉네임은 PlayerState의 현재 복제 이름을 표시한다.
- 로그인 후 연습 로비는 유지한다. 경기장 준비 중 걷기만 차단하고 화면을 가린다.
- 최종 결과 수신 확인 후 정상 finished 보고/세션 정리. 다른 사람이 나가도 로컬 결과를 유지하고 본인 확인으로 로비 UI를 다시 사용한다.
- 기존 NULL/LAN 경로의 같은 월드 진행과 호스트 복귀는 유지한다.
- 이 PC는 Unreal 미설치. 새 Editor 빌드·에셋 적용·실제 EOS 검증 완료를 주장하지 않는다.

## 작업과 검증

- [x] 순서·맵 whitelist·색상 정책 native 검사를 먼저 추가하고 runtime GI 상태를 구현한다.
- [x] 기존 GameMode에 준비/다음 라운드/결과 hook을 추가하고 EOS 맵 이동·스냅샷 복구·서버 4인 준비를 연결한다.
- [x] 이름표/복제 색상, 보존형 머티리얼 적용 도구와 보호 검사, 준비/최종 결과 UI를 연결한다.
- [x] EOS first-map 광고·검증, 정상 완료 수신 확인, 결과 유지·개별 로비 복귀를 연결한다.
- [x] 관련 문서 갱신, 가능한 로컬 검사, 독립 코드 리뷰.
- [ ] Unreal PC에서 새 Editor 빌드·native 검사·머티리얼 도구 적용 후 실계정 4PC 전 과정을 검증한다.

## 검토 초점

seamless 이동의 PC 재초기화와 타이머, PlayerId/점수 유지, 첫 맵 임의화와 세션 검색 검증, 이동 중 이탈/기한, 최종 RPC 수신 전 호스트 종료, 미완료 API의 멱등 재시도, 머티리얼 원본·연결 보존을 확인한다.

## 실행 기록

- Python Tint 보호 검사는 구현 전 모듈 부재로 실패했고 구현 후 6개 통과했다. 기존 관련 도구를 포함한 25개도 통과했다. native 검사는 Unreal 미설치로 실행하지 못했다.
- Ruling: 프로토콜 2의 세션 광고/승인 옵션을 추가한다. 기존 0.1.0 큐는 유지하되 구 실행 파일과의 잘못된 연결을 차단한다. 모든 테스트 PC가 같은 브랜치여야 한다.
- Ruling: 맵 이동과 최종 결과 수신 확인은 각 60초. 미확인 상태를 정상 완료로 보고하지 않는다.
- Ruling: 결과 UI의 개별 확인은 백엔드 terminal과 로컬 세션 정리 이후 허용한다. 인증 만료 중 결과 사본은 남기고 로그인 UI를 허용한다.
- 독립 정적 리뷰에서 TObjectPtr 순회 형식을 수정했다. 원격 클라이언트 NotifyLoadedWorld와 이동 전 UI/관전 카메라 참조 정리도 연결했다. 최종 검토에서 추가 확정 P0/P1은 없으며 실제 실행 검증을 대신하지 않는다.
