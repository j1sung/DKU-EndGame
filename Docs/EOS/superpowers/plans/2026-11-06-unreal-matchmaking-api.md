# Unreal 매칭 API 연결 구현 계획

> 실행: `superpowers:executing-plans`로 현재 세션에서 구현한다. 사용자는 중요한 설계 분기 외 일반 선택을 위임했다.

## 목표와 설계

최신 원격 dev(`f0515a6`)에서 `codex/unreal-matchmaking-api` 브랜치를 만들어 기존 로비 요청 이벤트를 실제 티켓 API에 연결한다. 기존 C++ HTTP·EOS 인증과 로비 상태/UMG를 재사용한다. 기존 작업 폴더를 사용하고 추가 worktree는 만들지 않는다.

- `standard`, `0.1.0`, 180초 대기와 배정 전 본인만 취소하는 계약을 유지한다.
- 네이티브 `FCFMatchmakingFlow`가 티켓 응답·멱등성 키·취소 의도·재시도를 처리한다. `UCFMatchmakingSubsystem`은 인증 컨텍스트, HTTP 1개, 타이머 1개와 로비 표시를 연결한다.
- 요청마다 Entry가 현재 계정의 Connect ID Token을 복사한다. 토큰은 Blueprint/로그/파일로 전달하지 않는다. 다른 계정으로 재로그인하면 과거 계정의 티켓과 쓰기 키를 폐기하고 새 계정 상태를 조회한다.
- 시작/취소 응답 유실 시 같은 키·본문으로 재시도한다. 생성 성공의 멱등 응답은 오래된 WAITING일 수 있으므로 GET current로 확정한다. 쓰기 결과를 모를 때 새 매칭을 허용하지 않는다.
- 정상 조회 간격 2초, 통신 실패 시 최대 5초 간격으로 3회 실패 후 수동 복구. Retry-After는 우선 적용한다. 로컬 시간 만료로 취소 성공을 만들지 않는다.
- 배정 시 취소 차단·matchId 보관·후속 세션 계층용 이벤트 전달. 세션 생성/참가와 게임 맵 이동은 이번 범위 밖이다. GET current를 계속해 서버 만료를 확정한 후에만 재시작을 허용한다.
- 인증 만료 시 불확실한 매칭을 취소 처리하지 않는다. 재로그인 화면으로 이동할 수 있게 하고, 돌아온 로비에서 현재 계정 상태와 미확정 요청을 복구한다.

## 작업

- [x] 티켓 처리와 경합·멱등성·응답 검증 회귀 검사 작성 및 네이티브 흐름 구현.
- [x] Entry의 C++ 인증 컨텍스트·만료 알림, HTTP·타이머 제공자 구현.
- [x] 기존 UI에 복구/인증 만료·계정 전환 연결, 기존 에셋 유지.
- [x] 관련 문서와 사용자 보고 성공 범위 갱신, 전체 변경 검토.

## 검증 기준과 제한

시작/WAITING/ASSIGNED/null/취소, 응답 유실, 쓰기 키 재사용, 이전 FlowId·HTTP 응답 차단, 401·429·잘못된 JSON, 서버 만료를 검사한다. Unreal 미설치 PC이므로 Unreal 빌드·자동화·실계정 실행은 직접 검증 불가다. 새 테스트는 Unreal 설치 PC에서 실행해야 한다. 인증된 실제 API 요청·AWS 변경·푸시·커밋·병합은 이번 요청에 포함하지 않는다.

## 결정 기록

- 배정 뒤 세션 기능이 아직 없으므로 현재 티켓을 계속 조회하며 서버 만료를 기다린다. 세션 완료를 가장하거나 전체 매치 이탈 API를 호출하지 않는다.
- 인증 만료 중 타이틀 이동은 재로그인 목적이다. 대기열 이탈/취소 성공을 의미하지 않으며 기존 매칭은 서버 정책에 따라 남을 수 있다.
- 전체 변경과 최종 보완을 별도 검토했으며 확정 가능한 추가 결함 지적은 없었다. Unreal 컴파일/UHT·자동화·실계정 실행을 통과했다는 의미는 아니다.
